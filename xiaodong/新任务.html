1. 术语与对象模型

整个任务模块只有四层对象，页面上的每一行都能对应到其中一层。除「模板编码」外，界面不展示任何编号；任务编号、执行编号、待办 ID 只用于后台、日志与导出。

对象主键产生方式说明
模板tpl_code在模板设计器中保存可复用的一套低代码表单 + 全局规则；唯一在界面上展示编号的对象
任务task_id一次「发布任务」产生承载发起人、执行人、规则与状态；单次任务只生成 1 条执行，周期任务按规则持续生成
执行exec_id任务按规则到点生成（或「立即发布第一条」）一次具体要干的活，有自己的计划起止与超期判定；界面统一称「本次执行」
待办todo_id执行 × 执行人，一人一条会签的最小单位；各人独立提交、独立超期；转办、调整执行人改变的是待办上的人
1.1 编码生成规则
编码格式生成时机与规则
模板编码TPL + 3 位序号
例 TPL001		租户内自增，从 001 起；首次保存成功时由服务端生成，前端只读、占位文案「（保存后自动生成）」；删除后序号不回收、不复用；超过 999 自动扩为 4 位（TPL1000）；并发用数据库序列 / Redis INCR 分配，禁止 max(code)+1；写入前校验唯一索引，冲突重试分配最多 3 次；生成后永不修改，编辑模板不改编码，复制模板生成新编码
任务编号单次 T+yyyyMMdd+3 位
周期 REC+yyyyMMdd+3 位		发布日期 + 当日流水，跨天重置；仅后台与导出使用，界面不展示
执行编号任务编号 + - + 3 位序号
例 T20260701007-001		同一任务下递增；生成后不可变；界面不展示
待办 ID执行编号 + - + 人员序号调整执行人时保留原 todo_id，只替换 person_id，便于追溯该待办的历史提交

所有编码只增不减；跨租户不共享序列；原型中的编号均为演示占位，开发按上表规则生成。

2. 状态定义与流转

2.1 任务级 4 态（界面上只会出现这 4 个词）
状态判定条件允许操作说明
进行中未到停止日期、未终止，且仍会生成执行编辑计划 · 暂停 · 终止单次任务在「实例尚未生成」时也是进行中
已暂停用户手动暂停，尚未恢复编辑计划 · 恢复 · 终止暂停即刻生效：当天未到点的执行不再生成；已生成的执行照常走完
已完成到达停止日期，不再生成新的执行查看 · 复制「已完成」只代表这个任务的执行已全部生成完毕，不代表执行都做完了；做完与否看执行层
已终止人工终止，不可恢复查看 · 复制停未来生成，已生成的执行照常走完
2.2 执行级 5 态（取值带进度）
状态判定条件说明
未执行已提交人数 = 0可撤回（0/n）
执行中 n/m0 < 已提交 < 执行人总数列内必须是 1/2 这种格式，n＝已提交人数、m＝执行人总数；不允许只显示「执行中」，否则看不出还差几个
已完成已提交人数 = 执行人总数会签闭环
已撤回未被任何人执行时被撤回不可再流转，仅可查看；从统计中剔除
已作废已有人提交后被作废不可再流转，仅可查看；从统计中剔除，但日志与提交记录保留
  1. 状态由服务端计算下发，前端不自行推导，只用于控制按钮显隐与标签颜色。
  2. 任务级不出现超期；超期只挂在执行级与人级（我的任务列表行＝我的待办）。
  3. 撤回 / 作废的后置效果：该执行从「应完成」统计中剔除，其超期一并剔除；执行日志永久保留。
  4. 撤回 vs 作废：只按状态二选一出现，不会同时出现。撤回＝无人动手时干净收回，需填原因、不通知执行人；作废＝已有人提交时强制失效，需填原因、通知执行人、不计入统计。

3. 超期判定

基准是「该条执行自己的计划结束时间」，不是任务整体的计划结束。每条执行的计划起止由首条按重复规则递推得出，生成时固化，之后改规则不回改历史。

维度用在哪判定
执行级台账执行明细、任务总览下钻、我的任务「我参与的」当前时间 > 该执行计划结束，且未闭环（仍有人未提交）→ 超期
人级我的任务「待我执行」「已执行」、执行人列表我没提交且当前时间 > 计划结束 → 我这条超期；我已提交则看我自己的提交时间是否晚于计划结束 → 晚于则标「超期完成」
  • 同一执行两处可以不一致：计划 17:00 结束，我 16:20 交、他人 18:00 交 → 我的任务里我未超期，台账里该执行超期。这是刻意的——一个回答「我有没有按时」，一个回答「这一趟有没有按时」。
  • 超期完成后仍永久保留标记（绩效追溯需要），不做清除；撤回 / 作废后随统计剔除。
  • 允许并存：上一条未闭环、下一条已到开始时间，各自计算、互不影响。
  • 超期只影响标红、提醒、统计，不限制提交、转办、调整执行人、撤回、作废。
  • 计算时机：写入时打标 + 定时任务（建议每 5 分钟）刷新；前端只读，不做超期计算。

4. 统计口径

指标口径
应完成执行数执行一生成即计入；撤回 / 作废后剔除（不再计入应完成，其超期一并剔除）
完成率已完成执行数 ÷ 应完成执行数；分母不含已撤回 / 已作废
超期数按执行条数计：一条执行无论几人超期只算 1 条；人员维度另算「超期待办数」
会签完成以整条执行闭环为准，不看谁先交、不看平均提交时间
数据来源一律以服务端聚合结果为准，前端不累加、不缓存、不参与口径计算

5. 人员选择器（组织架构）

执行人、参与人员、转办接收人、调整后的执行人、提醒人统一使用同一个组件。

项规则
形态左侧部门树 + 右侧人员列表 + 底部已选区；支持按部门整选、按姓名 / 工号搜索
候选人仅在职人员；停用 / 离职不出现在列表；已选人员若离职，标签标灰并提示「需更换」
存储只存 person_id；展示名重名时追加部门，如「李强（机电队）」
数量执行人 ≥ 1 人（必填）；参与人员可为 0；转办接收人、调整目标单选 1 人；提醒人 ≥ 1（开启提醒时）
互斥转办接收人 ≠ 转出人，且不能已在执行人名单中；调整目标不能与现有执行人重复（被替换者除外）。参与人与执行人允许重复，不做互斥校验
变动人员调岗 / 离职不回溯已生成的执行；只影响之后生成的执行
空值未选时显示占位「点击选择执行人 / 参与人」，不显示「已选 0 人」

6. 低代码表单与设计器机制

  • 模板即一套低代码表单：字段的标题、类型、必填、长度、正则、选项、联动、默认值全部在「表单设计器」里配置，任务模块不重复定义这些规则。
  • 存储：模板保存时把画布结构序列化为 components（JSON）；发布任务时把 tpl_code + 变量值存为任务快照。
  • 快照锁定：任务发布后表单结构锁定，之后修改模板不影响已发布任务，只影响之后新建的发布。
  • 渲染：执行页、只读提交页都按快照的 components 顺序渲染，标题、必填、控件类型与设计器一致。
  • 双重校验：前端按组件规则先校验一次，服务端按同一份 schema 再校验一次，不信任前端。
  • 无表单：form_id 为空时，执行页只显示「执行完成情况 + 现场附件」。
  • 原型说明：原型里的「巡检区域 / 设备状态 / 安全隐患 / 处理措施 / 备注」是演示字段，不代表真实表单结构，开发不要写死。

场景格式 / 规则
时区Asia/Shanghai；服务端存 UTC 时间戳，出参转本地时间字符串
日期YYYY-MM-DD

8. 列表通用规则

  • 排序：所有列表都不提供表头排序（点表头无响应、不出现升降序箭头），一律服务端固定排序，规则如下——
    · 执行级列表（待我执行 / 已执行 / 已转发 / 我参与的 / 台账执行明细 / 执行明细弹窗）：按发布时间倒序，同一发布时间按执行编号倒序；
    · 任务级列表（草稿任务 / 我发起的 / 任务总览 / 模板列表）：按创建时间倒序，同一时间按编码倒序；
    · 执行日志：未提交的行置顶，其余按动作时间倒序；
    · 超期不参与排序（只做红色标记），避免列表每 5 分钟扫描一次就整体跳动。
  • 分页：服务端分页，默认 20 条 / 页；切换查询条件后回到第 1 页。
  • 关键字：模糊匹配，忽略大小写与首尾空格；多个关键字以空格分隔时按「与」匹配（归一化多余空格）。
  • 筛选组合：不同条件之间「与」；同一条件多选时「或」。
  • 结果数：筛选条右侧实时显示「共 N 条」，指筛选后的总条数，不是当前页条数。
  • 空态：无数据「暂无数据」；筛选后为空「没有符合条件的结果」+「重置」按钮。
  • 导出：仅任务总台账支持；导出当前筛选结果全量（不分页），上限 5 万行，超出提示「结果过多，请缩小范围」；文件名 任务总览_yyyymmdd_HHmm.xlsx / 执行明细_yyyymmdd_HHmm.xlsx。
  • 列宽：时间列固定宽度、不换行；名称列自适应并可省略，hover 显示全文。

重复日期（按周）下拉多选是周一 ~ 周日至少 1 项；按钮显示摘要（≤3 项直接列，>3 项显示「已选 N 项」）；弹层含全选 / 清空 / 确定

重复日期（按年）多行规则是每行＝月份多选 × 日期多选至少 1 行，最后一行不可删；行数 ≤ 10、展开的「月 × 日」组合 ≤ 60，超出提示「规则过于复杂，请精简」；同一行内是笛卡尔积（1月+3月 × 10日+15日 → 4 个日期），要「1月10日 + 3月15日」请拆两行；不同行展开出相同日期自动去重；2/30、4/31 等无效日期自动跳过、不报错

4.6 时间递推规则（每条执行的计划起止怎么算）

任务上的「计划开始 / 结束」＝第一条执行的起止；两者差值＝每条执行的统一时长。后续每条：日期按频率后推，时刻与时长沿用首条。

频率首条第 2 条及以后
按天2026-10-19 13:15 → 2026-10-20 13:15
（时长 24 小时）		2026-10-20 13:15 → 2026-10-21 13:15；2026-10-21 13:15 → 2026-10-22 13:15 …
按周（周一 + 周三）每周 2 条，时刻均为 13:15（10-21、10-26、10-28 …）
按月（1 号）2026-11-01 13:15 → 2026-11-02 13:15；2026-12-01 13:15 → 2026-12-02 13:15 …
按年（3 月 1 日）次年 2026-03-01 13:15 → 2026-03-02 13:15 …
  • 发布 ≠ 开始：允许 08:00 发布、13:15 才开始；两者间隔固定，都等于提前量。
  • 生成即固化：执行的计划起止在生成那一刻写入，之后改规则不回改历史。
  • 「下一次任务详情」：按当前表单实时推算下一条的发布时间与计划起止，从右侧滑出只读面板（内容即基本信息配置的克隆，全部置灰）。未开重复发布、或未填计划起止时按钮置灰，hover 提示「开启重复发布、并填写计划开始/结束时间后可预览」。
4.7 全局规则 · 任务提醒

先定口径：所有提醒都挂在每一条执行上，基准是该条执行自己的「计划开始 / 计划结束」，不是任务整体的起止；同一执行 × 同一提醒类型 × 同一提前量，只发一次。

字段控件必填取值 / 格式取值逻辑
自动推送提醒开关—默认开启总开关：关闭后「计划开始前 / 计划结束前 / 超期未处理」三类提醒全部不发送，已排队的提醒一并作废；重新开启只对之后到点的时机生效，不补发历史提醒
计划开始时间前多选 + 自定义开启提醒时 ≥ 1 项不提醒 / 准时 / 提前 10 分钟 / 30 分钟 / 1 小时 / 2 小时 / 1 天 / 2 天 / 自定义（1–999 分钟·小时·天）触发时刻＝该执行的计划开始 − 提前量；「准时」＝计划开始当刻。多选时每个选项各发 1 次（同时选「提前 1 天」和「提前 1 小时」→ 发 2 次）。「不提醒」与其它项互斥，选中后清空其它选择
计划结束时间前多选 + 自定义开启提醒时 ≥ 1 项同上触发时刻＝该执行的计划结束 − 提前量；其余规则同上
提醒人组织架构多选开启提醒时 ≥ 1 人—默认带入该任务的执行人，可改为其他人；只存 person_id；发送时跳过离职 / 停用人员并记日志

发送规则（开发 / 测试对照）

  • 扫描频率：定时任务每 5 分钟扫描一次，取「触发时刻落在 (now, now+5min] 区间」的提醒发送；同一分钟内到点的多条合并处理。
  • 触发时刻早于执行生成时间：该条提醒不发送（例如配置「提前 2 天」，但执行只在 1 天前才生成，则此提前量对本条无效）。
  • 错过窗口：因服务停机等错过扫描 → 在基准时刻后 60 分钟内补发 1 次；超过 60 分钟直接丢弃，并记一条「提醒过期未发送」日志。
  • 不发送的情形：该执行已闭环（全员提交）、已撤回、已作废，或任务已终止。
  • 幂等：唯一键＝执行编号 + 提醒类型(start/end) + 提前量秒数；重复扫描或服务重启不会重复发送。
  • 时间口径：Asia/Shanghai，分钟级精度、不显示秒；跨天按自然时间计算（提前 1 天＝24 小时）。
  • 渠道：站内通知 + 待办角标（渠道由通知中心统一，本模块只负责「何时、发给谁」）。
4.8 全局规则 · 超期未处理提醒

什么叫「超期」：某条执行已过自己的「计划结束时间」（now ≥ plan_end）且没有全员提交（未闭环），这条执行即进入超期状态。
对个人而言：我未提交 → 我的待办超期；我已提交但提交时间晚于 plan_end → 标记「超期完成」（仍算超期，永久保留标记）。

字段控件必填取值 / 格式取值逻辑
超期未处理下拉单选 + 自定义非必填（默认不提醒）不提醒 / 每 10 分钟 / 每 30 分钟 / 每 1 小时 / 每 1 天 / 自定义（每 N 分钟·小时·天，1–999）进入超期后按此间隔重复提醒。第 1 次提醒时点＝plan_end + 间隔（计划结束 17:00、选「每 30 分钟」→ 17:30 第 1 次、18:00 第 2 次）
重复次数数字非「不提醒」时必填1–10，默认 2总发送次数（含第 1 次）；达到上限后不再发送，直到执行状态变化

判定与停止

  • 判定基准：该条执行的 plan_end；不使用任务整体的计划结束时间，也不用「最后一个人提交的时间」反推。
  • 进入超期的时刻：now ≥ plan_end 且未闭环，精确到分钟。
  • 停止条件（满足任一）：执行闭环（全员提交）／执行被撤回／执行被作废／任务被终止／达到重复次数上限。
  • 超期后仍可提交：提交成功后该人的超期提醒立即停止；状态打「超期完成」标记且永久保留（绩效追溯）。
  • 不计入超期：已撤回、已作废的执行（同时从「应完成」与「超期」统计中剔除，日志保留）。
  • 发送对象：该执行仍未提交的执行人 + 已配置的提醒人（去重，排除离职 / 停用）。
  • 幂等：唯一键＝执行编号 + 超期提醒第 N 次；重复扫描不重复发送。

一条可复现的例子：计划结束 2026-10-20 17:00，配置「每 30 分钟、重复 2 次」；执行到 17:00 仍有人未交 → 17:30 发第 1 次、18:00 发第 2 次后停止；若 17:45 全员交齐，则 18:00 那次不再发送。

5. 交互与联动

  1. 标签切换：基本信息与全局规则之间切换不丢已填值；不触发保存。
  2. 频率切换：按天 / 周 / 月 / 年之间切换时，已选日期值保留在内存，切回原频率自动恢复；切到「按天」时日期控件隐藏但不清空。
  3. 按年多行：「+ 添加一条」在末尾追加一行空规则（月份、日期均未选，参与校验）；每行右侧 ✕ 删除，最后一行不可删。
  4. 停止日期与永不截止：勾选「永不截止」→ 日期输入禁用并清空展示；取消勾选 → 恢复输入，需重新选择。
  5. 未保存提示：任何标签下改动后返回，都按「有未保存修改」处理。
  6. 预览：「下一次任务详情」读取的是当前表单值（不是已保存值），因此改完立刻能看效果。

暂停 / 恢复 / 终止都要二次确认：暂停＝「暂停后不再生成新的执行，已生成的照常进行，可随时恢复」；恢复＝「恢复后从下一条按规则继续生成，暂停期间的不会补生成」；终止＝「终止后不可恢复，已生成的执行照常走完」+ 必填终止原因（2–200 字），原因写入任务操作记录。三者口径与「任务总台账 · 4.5」完全一致，两处入口共用同一套实现。

为什么复制对所有状态开放：复制是「以现有配置新建一条任务」，与任务当前是否在跑无关——进行中的任务同样可能需要"再发一份一样的"（如临时加一个班组）。复制不改变、不暂停、不影响原任务；新任务从发布时刻起按自己的规则生成执行，名称默认加「（副本）」。

为什么已生成过执行就不能改表单类型：执行生成时锁定表单快照，同一任务下每次执行必须使用同一套字段结构。若允许中途改表单类型，会出现在同一任务里"前几次是老表单、后几次是新表单"，历史提交无法按同一结构展示、导出与统计。若真实诉求是"换张表重新发"，请用「复制」新建任务——历史任务保持原样。其余字段（名称 / 执行人 / 参与人 / 计划起止 / 重复规则 / 提醒）仍可编辑，且只影响之后生成的执行。

查询：关键字 + 类型 + 状态。排序：固定按创建时间倒序，不提供表头排序。

5. 交互与联动

5.1 发布前校验（顺序执行，命中即停并聚焦）
  1. 任务名称非空 → 「请填写任务名称」
  2. 执行人 ≥ 1 → 「请选择执行人」
  3. 计划开始、结束均有值 → 「请填写计划开始 / 结束时间」
  4. 结束 > 开始 → 「计划结束时间必须晚于开始时间」
  5. 开始 ≥ 当前时间 → 「计划开始时间不能早于当前时间」

5.2 提交结果
动作结果
发布任务创建任务（生成任务编号）→ 按「立即发布第一条」或发布时间生成首条执行 → 跳「我发起的」并高亮该行 → Toast「发布成功」

2. 页面目标

这是执行侧的唯一入口，只回答一个问题：和我有关的事，现在到哪一步了。因此本页只有执行级信息（发布时间、状态、超期、我的提交时间），不出现任务级的暂停 / 终止 / 编辑计划。

互斥归属：同一条执行对同一个人只出现在一个标签——我是执行人且未交 → 待我执行；已交 → 已执行；已转出 → 已转发；仅是参与人 → 我参与的。这样不会被误认为数据重复。

3. 区块结构

  1. 页签栏：4 个标签，单层平铺；「待我执行」带待办数角标。
  2. 查询条：按标签定制，条件与匹配规则见 4.6；含结果数与重置。
  3. 列表：四个标签各用各的表头，列结构不共用，见 4.1 ~ 4.4。

5. 交互与联动

  1. 标签切换：只换数据与查询条，保留各自查询条件；切换后回到第 1 页。
  2. 下钻一致：任务总览的「已发布次数」与执行明细的「执行人」是唯一两个可点下钻字段，其余列不做跳转，避免误点。
  3. 操作后刷新：任何写操作成功后，刷新当前列表与相关计数（已发布次数、角标），不整页重载。
  4. 导出：按当前标签与当前筛选条件导出全量，导出期间按钮 loading 并禁用。
  5. 管理员越权操作：可对任何人发起的任务执行暂停 / 终止，可对任意执行撤回 / 作废 / 调整，不受发起人限制；但每次写操作都记审计日志。
