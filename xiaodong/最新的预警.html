1. 交付说明（不面向用户）

页面 ID
page-warning-info-table（仅原型示意，不进入正式产品）
交付形态
不提供用户界面：正式产品中没有这个页面、没有这个菜单
本页用途
向开发说明：系统需要一张预警信息表，用于存储每一条预警的记录
数据归属
预警主表（一条预警一行）+ 处置子表（一位处理人一行）
唯一数据源
预警任务、预警信息表统计、分级看板、按工作表统计、导出，全部读这张表
原型里的「列表 / 表单设计器 / 只读视图」只是让开发直观看到数据结构，不要按这套页面交互去实现。字段严格按原型上区、下区所列为准，不做增补。

2. 建表目标

规则引擎每命中一个条件组，就向预警主表写入一条记录；处理人每提交一次处置，就向处置子表写入一条记录。这张表是全系统预警数据的唯一来源。

  • 主表 = 一条预警的完整档案：字段在生成时固化，后续不可修改。
  • 子表与主表 1:N：按处理人维度各存一条，多人并行提交互不覆盖。
  • 两表用「预警编号」关联：编号是这条预警的唯一标识，台账、任务、导出都以它为键。

3. 表结构

3.1 预警主表

一条预警一行，存触发时的基础信息（上区 10 个字段）。

3.2 处置子表

一条处置一行，按处理人拆分（下区 5 个字段）；前端「处理人列表 / 个人处置详情」都读这张表。

4. 字段规格

通用规则：长度按字符计；文本入库前 trim()；时间统一 YYYY-MM-DD HH:mm（带年份，精确到分钟），存储用 datetime，展示再格式化。

4.1 预警主表（与原型上区一致，10 个字段）
字段类型必填长度 / 格式来源与约束
工作表名称字符串是≤ 30 字取触发本次预警的源工作表名称，生成时固化
预警内容字符串是≤ 50 字取规则条件组的「预警内容」，即这条预警的标题，生成时固化
工作项字符串是≤ 20 字取命中的工作项；命中多项时存「首项 + 等 N 项」的展示值
预警发生时间datetime是YYYY-MM-DD HH:mm= 表单提交并通过条件判定的时间；建索引，列表与统计默认按此倒序
预警值（阈值）字符串是≤ 30 字规则里配置的判定阈值（含单位）；多项时为「首项 … 等 N 项」

5. 写入与约束

  1. 写入时机：表单提交 → 规则判定 → 命中条件组 → 同一事务内写入主表 1 条 + 按处理人写入子表初值；任一环节失败整条回滚，不允许出现「有主表无处理人」的半成品。
  2. 生成后只读：主表 10 个字段全部在生成时固化，后续不可修改；需要修正只能作废后重新触发。
  3. 子表一人一行：处理人提交处置时插入一条；同一「预警编号 + 实际处理人」重复提交按幂等处理，只保留首次，后续返回「该预警已提交处置」。
  4. 附件与签字：只存文件 ID，不存二进制；文件服务删除需与记录生命周期绑定，记录未删除时文件不可物理删除。
  5. 读取方：预警任务、预警信息表统计、分级看板、按工作表统计、Excel 导出，统一读这两张表，不做二次冗余。
  6. 数据量：主表按年增长，建议按「预警发生时间」做分区或归档，历史数据只读保留。

处置状态标签·只读未处理 / 已处理按该处理人是否有处置记录判定：有 →「已处理」（绿），无 →「未处理」（红）。这是个人状态，不是整条预警状态
提交时间文本·只读YYYY-MM-DD HH:mm该处理人自己提交处置的时间；未提交显示「—」；与「触发时间」「处理期限」含义不同
处理详情链接—已提交 → 蓝色「查看」，打开个人处置详情（4.5）；未提交 → 灰色「未提交」，不可点

空态与限制：无数据时显示「暂无数据」；弹窗只读——不提供删除或批量操作（调整处理人在台账行尾「操作」列、重新指派在「分派异常」Tab，两者都不在本弹窗内做）；底部只有「关闭」。

4.3.2 调整处理人弹窗（台账行尾「调整处理人」打开）

入口：预警台账行尾「操作」列 → 「调整处理人」。标题「调整处理人 - WRN-YYYYMMDD-NNN」。用途：管理员纠错——人已经派出去了但派错了（离职、岗位调整、长期不办）。

字段控件必填长度 / 格式取值与校验
待调整的处理人下拉是单人只列未提交处置的处理人，格式「姓名（来源类别）· 未提交」；已提交处置的人不可调整（其处置已留痕，不可篡改）；仅 1 人未提交时自动选中
调整为选人按钮（可点击只读框）是单人未选显示灰色「请选择人员」；点击打开组织架构选人弹窗（见下方 4.3.3），选完回填姓名、文本框转为已选态；未选直接确认提示「请选择调整后的处理人」
调整原因多行文本否≤ 200 字选填，不填也能提交；填写后写入处理日志的「调整处理人」条目（原因：…），未填则日志只记「原处理人 → 新处理人（原类别：X）」

确认后：① 只替换该处理人条目的人名，保留待办条目、处理期限、派单快照时间，来源角色类别记为「企业管理员调整 · 原类别 X」，处置状态回到「未处理」；② 写入一条「调整处理人」处理日志（原处理人 → 新处理人、操作人、时间、原因）；③ 通知原处理人与新处理人；④ 台账「处理人」列实时刷新。处理人总数、任务状态、超期判定均不变。

区块内容说明

② 命中明细（只读表）同 4.4 第②区块同上

4.6 处理日志（任务详情底部，只读）
项规则
归属属于预警任务，一条任务一份日志；只出现在「任务详情」与「处理（编辑）」两个界面，个人处置详情、处理人明细里都不显示。日志记录整条任务从触发到闭环的全过程，不属于某一个处理人
位置任务详情弹窗最底部、页脚按钮之上；默认收起，点标题行展开 / 收起
摘要行「处理日志 · 共 N 条 · 最新动作 YYYY-MM-DD HH:mm · 只读留痕」
每条内容时间 / 操作人 / 来源角色类别 / 动作 / 说明；按时间正序排列（早 → 晚）
记录哪些动作仅五类关键节点：触发预警（系统）、处理预警（处理人提交处置）、转发预警（转发人 + 被转交人 + 转办说明）、调整处理人（管理员 + 原处理人 → 新处理人 + 原因）、作废预警（作废人 + 原因）
可见范围处理人与管理员都能看到，包括他人提交处置的摘要（如「已提交处置（已补装防护栏并加固）」），便于相互了解进度
不记录查看详情、下发通知、派单解析、超期提醒等过程动作，避免日志被噪音淹没；「分派异常 → 重新指派」不写日志（该条从未进入任何人待办）
不可篡改只读、不可修改、不可删除；人员按派单快照显示（组织架构变动不改变历史记录）
转发历史转发只在这里展示：每次转发生成一条「转发预警」日志，含转发人 / 被转交人 / 时间 / 转办说明（说明 ≤ 200 字，可为空）
调整历史「调整处理人」也在这里展示：每次调整生成一条日志，含操作人 / 原处理人 / 新处理人 / 时间 / 原因（原因 ≤ 200 字，必填）
4.7 状态与超期（台账口径）

台账展示的是整条预警的任务状态，由处置子表汇总得出（状态不是手工填写的字段）。

状态判定条件展示说明
未处理已提交人数 = 0红色标签「未处理」处理期限内未提交时追加「已超期」徽标
处理中0 < 已提交人数 < 处理人总数橙色标签「处理中」只在「全部完成」模式且处理人 ≥ 2 时出现；单人任务不会出现
已完成达到处置模式的完成条件绿色标签「已完成」超过期限完成时追加「超期完成」徽标
已作废管理员执行作废灰色标签「已作废」终态、不可恢复；只在台账与导出中保留，预警任务页不展示
4.7.1 处置模式对完成条件的影响
处置模式（规则里配置）完成条件其余处理人
并行处置 · 任一完成任意 1 人提交处置即「已完成」未提交者的待办自动关闭，不再要求提交
并行处置 · 全部完成全部处理人都提交才算「已完成」少一人即为「处理中」，未提交者继续保留待办
4.7.2 超期：台账用「任务口径」，任务页用「个人口径」
使用位置口径规则
台账 / 下钻明细 / 分级看板任务口径未完成且当前时间 > 处理期限 →「已超期」；已完成且最后一位处理人的提交时间 > 处理期限 →「超期完成」；其余不显示徽标
预警任务页个人口径本人未提交且当前时间 > 处理期限 →「已超期」；本人已提交且本人的提交时间 > 处理期限 →「超期完成」；随登录人不同而不同
  • 「处理期限」字段只存时间：不写「已超期」等文字、不标红；是否超期一律由独立徽标表达。
  • 超期是动态值：未完成任务随时间推移会自动由「未超期」变成「已超期」，因此读取时实时计算，不在主表固化。
  • 状态不可回退：已完成后不能回到处理中；处置有误需作废后重新触发。任意状态均可被管理员作废（已完成也可），作废时处置记录保留。

字段取值与校验

5. 交互与联动

  1. Tab 切换：台账 / 分派异常数据独立，角标数字 = 待指派条数。
  2. 展开命中明细：点「预警工作项」整格展开／收起，交互与预警任务一致，展开行 colspan = 13。
  3. 点预警编号 → 任务详情：打开 4.4，看整条任务的基础信息、命中明细、全部处理人与处理日志。
  4. 点处理人 → 处理人明细：「只看人」的快捷路径，打开 4.3 的轻量弹窗，不加载任务详情、不带日志。
  5. 处理人行「查看」→ 个人处置详情：仅已提交的行可点（处理人明细与任务详情两处都可点），打开 4.5，只显示该人的处置内容与附件；未提交行不可点。
  6. 行尾「调整处理人」：打开 4.3.2 调整处理人弹窗；只列未提交处置的人可选；确认后换人、写入一条「调整处理人」日志、通知新旧处理人，台账「处理人」列实时刷新；处理人总数、任务状态、超期判定、处理期限均不变。
  7. 行尾「作废」：打开 4.10 作废弹窗，作用域 = 本行 1 条；确认后本行状态变「已作废」、该行勾选框禁用、两个操作按钮置灰，并写入一条「作废预警」日志。
  8. 转发历史：只在任务详情的处理日志中查看，处理人列表里以「转发自 XX」标注来路。
  9. 处理日志：在任务详情最底部，默认收起，点标题行展开；无筛选、不可编辑；处理人明细与个人处置详情里都没有日志。
  10. 作废：勾选 → 点「作废」→ 填原因 → 确认（批量）；或直接点行尾「作废」（单条）；这些预警状态变「已作废」，从预警任务全部页签移除，台账保留。
  11. 导出：台账导 Excel；异常 Tab 单独导出异常清单；导出内容与列表字段一致，不含日志与处置明细。
  12. 指派：确认后状态变「已指派」、生成指派记录；本条进入被指派人待办，不写入处理日志，只刷新异常清单。
  13. 只读边界：本页所有操作均为管理动作（作废 / 调整处理人 / 指派），不能代替处理人提交处置，也不能修改处置内容或删除附件。

3. 区块结构

  1. 页签栏：未处理 / 通知我 / 已处理 / 我转发。「未处理」「通知我」带数量角标，数字为当前登录人在该页签下的待办条数，实时计算。
  2. 查询条：时间维度 + 日期范围 + 预警工作项 + 风险等级 + 查询。筛选只作用于当前页签。
  3. 任务列表：10 列固定结构，见 4.1。
  4. 命中明细展开行：点「预警工作项」整格展开，插在该行下方，不新开弹窗。
  5. 处理人列表 / 处理人明细：点「处理人」单元格打开轻量弹窗（见 4.5）；任务详情第③区块是同一份数据的内嵌版。
  6. 任务详情弹窗：点「处理 / 查看」打开；编辑态与只读态共用同一组件，见 4.4。
  7. 转发弹窗：仅「未处理」页签点「转发」打开，见 4.6。

4. 字段规格

通用校验规则：长度一律按字符计（中文、英文、标点各计 1 个）；所有文本在提交前执行 trim() 去首尾空格；必填为空时按钮置灰不可提交，并提示「请输入{字段名}」/「请选择{字段名}」；错误提示统一为字段下方红色 12px 文案；日期时间一律 YYYY-MM-DD HH:mm（带年份，不省略年份），精确到分钟，秒不展示；列表、台账、下钻、处理人列表、日志等所有展示位置统一使用该格式。

5. 交互与联动

  1. 页签切换：只换数据，列结构不变；切换时保留查询条件，不保留滚动位置。
  2. 展开命中明细：点「预警工作项」整格展开/收起，鼠标悬浮整格变主色；命中 1 项与多项交互完全一致。
  3. 打开处理人明细：点「处理人」单元格任意位置，打开只列人的轻量弹窗；点其中「查看」进入个人处置详情（叠在其上，关闭后回到处理人明细）；要看整条任务则点预警编号。
  4. 处理：进详情编辑态 → 填写处理情况 → 上传附件 → 签字 → 提交。提交成功后：该处理人状态置为已处理、写提交时间；若全部处理人已提交，任务状态转「已完成」，从所有待办中消失；超期判断同步刷新。
  5. 查看：进详情只读态，隐藏填写区与「提交处置」，页脚只有「关闭」。
  6. 转发：选定人员 + 可选说明 → 确认 → 新处理人进入待办、原处理人退出、写入一条「转发预警」日志；操作不可撤回。
  7. 提交防重：提交按钮点击后置灰并显示 loading，接口返回前不可重复提交；重复请求按「同一处理人同一预警」幂等处理。
